## [02] ACTIVE POSITION — FINANCE AI PLATFORM

> A private finance AI workspace built around the way I actually trade: charts, catalysts, headlines, earnings, memory, risk, and execution context in one operating surface.

This is no longer just a finance-themed assistant concept. The current project is a real multi-surface platform with live channels, persistent chat, mode-specific reasoning, finance data integrations, and a custom terminal-style UI.

### Current Surface

| Channel | Function |
| --- | --- |
| `ai-trading-chat` | Main finance chat with live market context and image-aware input |
| `trade-check` | Pre-trade validation and decision support |
| `market-scanner` | Candidate scanning and opportunity filtering |
| `trading-stats` | Performance and account-level trading overview |
| `database-view` | Journal, stored research, and memory-facing data views |
| `ai-training` | Feedback and training loop for improving system behavior |

### Current System Layer

| Layer | Live Setup |
| --- | --- |
| Primary model | `Gemini 3 Flash` via `OpenRouter` |
| App modes | `AI Chat`, `Trade Check`, `Scanner`, `Earnings`, `Earnings Reaction` |
| Persistence | `PostgreSQL` for auth + chats, local finance storage for research and runtime data |
| Memory | `Chroma` research memory + behavior/context persistence |
| Frontend | `Flask`, `Jinja`, `HTMX`, custom terminal-style interface |
| Core bias | finance-first routing, not general-purpose chat |

### Signal Inputs

- Alpaca market data
- Finnhub company and market endpoints
- Twelve Data for earnings-reaction flow
- Financial Modeling Prep research data
- Tavily and Google search layers
- chart, news, quote, and event context merged into one desk

### Why It Exists

- reduce noise before execution
- keep finance context attached to the decision
- track chats and evolving reasoning over time
- build a sharper link between research, memory, and trades
- create a private operator stack before deciding what should ever be public

## [04] MODEL DESK

`Python` `JavaScript` `HTML` `CSS` `Flask` `HTMX` `PostgreSQL` `Chroma` `OpenRouter` `Gemini`

The model layer has moved forward from the older setup. The current project is built around `Gemini 3 Flash` through `OpenRouter`, with mode-specific runtime tuning across chat, scanner, trade-check, and earnings flows.

That matters because this repo is not about using one static model in one static way. The point is to route the right behavior for the right market task: fast surface response where needed, deeper context handling where needed, and tighter control over how memory, prompts, tools, and live data come together.
